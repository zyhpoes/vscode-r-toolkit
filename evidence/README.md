# evidence/ —— 实测证据

这里的文件是**"R / R6 行为"结论的出处**：每个 `demoN.R` 都用真实的 R 跑出来，
不是凭记忆或推理写的。规则见 `AGENTS.md` 的「实测证据」一节。

## 怎么用

```bash
Rscript evidence/demoN.R
```

- 默认这台机器已经装好 R 与所需包（如 R6）；缺了就让 R 自己报错 —— 报错本身也是证据。
- 脚本里**不写**"找库 / 探测"之类的兼容逻辑，也不写死任何人的本机路径。

## 实测环境

脚本开头不写环境（保持精简），版本统一记在这里；环境变了就更新这张表：

| 项 | 版本 |
|---|---|
| R | 4.6.1 (2026-06-24 ucrt) |
| R6 | 2.6.1 |

## 写新证据

- 新建 `demoN.R`（N 递增），文件**开头注释**写清：
  这个 demo 在验证什么（疑问）、结论是什么、不可靠的部分（如果有）
- 结论若被新实测推翻：**改脚本 ✓ 改这里的摘要 ✓ 并在注释里写明"原来以为 X，实测是 Y"**，不要悄悄删旧结论
- 新增 / 改动后，在本文件的"清单"里补一行

## 清单

| 脚本 | 验证什么 | 结论摘要 |
|---|---|---|
| `demo1.R` | R6 的 `active` / `public` / `private`：定义规则、重名、跨继承、可见性 | ① `active` 每项必须是函数（否则定义时报错）② 同类内三列表名字必须全局唯一（定义时报错）③ `public`↔`active` **跨继承**同名 → `$new()` 时崩（`symbol already has a regular binding`）④ 同类性质同名合法，子类覆盖 + 动态派发 ⑤ `active` 在公共侧（`ls` / `super$` 都能看到）⑥ `active` 的写是调 setter，不会存值 ⑦ `父 private`↔`子 private` 同名**行为不可靠**（一次 `child:private`、一次 `NULL`）→ 别这么写 |
| `demo2.R` | R 的表达式语法元素清单（自己写语法树之前，让 R 的 `getParseData()` 报一遍） | ① 共 22 条元素，多数是词法级 ② `TRUE` / `FALSE` / `NA` / `Inf` 都是 `NUM_CONST`（不是名字）③ `x$y` 的 `y` 是 `SYMBOL`，只有 `x@y` 的 `y` 才是 `SLOT` ④ `f(a, )` 合法；`(a)` 不产生额外节点 ⑤ `x |> f()` 是独立的 `PIPE` token（与 `%>%` 区分）。末尾带 `stopifnot` 断言，R 升级后行为变了会直接报错 |
| `demo3.R` | R 的运算符优先级与结合性（parser 的算符优先表） | ① 第 0 节先用 `*` vs `+` 走一遍"怎么判断谁更紧"② 矩阵用 `row` / `col` / `=` / `?` / `self` 标记 ③ 共 14 档（第 1 档最紧）：`^` ＞ `:` ＞ `%in%` ＞ `* /` ＞ `+ -` ＞ 六个比较运算符 ＞ `& &&` ＞ `\| \|\|` ＞ `~` ④ 三个概念带真实数值：左结合（`10-3-2` = 5）✓ 右结合（`2^3^2` = 512、`a <- b <- 5`）✓ 不可连用（`a < b < c` 是语法错误）⑤ `^` 比一元 `-` 紧（`-2^2` = -4）；`x \|> f()` 等价 `f(x)` |

## 为什么放在仓库里

- 这些结论会直接决定代码怎么写（例如我们为什么把 `active` 与 `public` 归为同一可见区）
- 放仓库里 = 换机器 / 换人 / 以后自己都能**复跑**核对，而不是去翻对话记录
- 它们**不参与** `npm run build` / `typecheck` / `lint` / `test`（工具只认 `.ts`），
  所以需要人主动跑 —— 这也是本文件存在的意义
