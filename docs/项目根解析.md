# 项目根解析（box 模块定位）

> 状态：候选根三层解析、`.Rprofile` 查找、模块文件定位**已实现**；
> **点击模块名跳转尚未实现**（进度见 `DESIGN.md`）。改动本文件规则需经用户同意。

## 目标

算出 box 根 → 拼 `根 + 模块路径 + .R` → **试文件是否存在** → 存在才跳。
判定依据是「文件存在」，不是「算对 `box.path` 的值」。

## 候选根优先级

| 顺序 | 来源 | 规则 |
|---|---|---|
| 1 | `settings.json` 的 `r-toolkit.boxPaths` | **字符串数组**（与 box 的 `box.path` 一样是向量）；**配了就只用它**，数组内按书写顺序依次查找 |
| 2 | 最近的 `.Rprofile` 的 `options(box.path = ...)` | 从当前文件向上找，**边界是文件所属的工作区文件夹**（含边界那一级）；文件不在任何工作区里 → 本层不给结果。**范围：只解析项目级 `.Rprofile`**（不读用户级 `~/.Rprofile` 与 site 级 `Rprofile.site`）——靠"上溯到工作区根为止"落地 |
| 3 | VS Code 工作区根 | 多根工作区 → 全部作为候选 |

多候选时逐个试文件，**第一个存在的胜出**；全都不存在 → 不跳转。

## `r-toolkit.boxPaths` 每个条目的三种写法

| 写法 | 算出的根 |
|---|---|
| `"D:/workspace/demo"` / `"/home/me/demo"`（绝对路径） | 原样 |
| `"R"` / `"./R"` / `"../shared"`（相对路径） | 按**工作区根**解析；多根工作区 → 每个根各一个候选 |
| `"${workspaceFolder}"` / `"${workspaceFolder}/R"` | 替换成工作区文件夹（多根工作区 → 每个都是候选）；该占位符由**我们**替换（VS Code 不会替扩展展开） |
| `"${env:HOME}/x"` 等其它变量 | **不支持，也不猜** → 该条目作废（其余条目不受影响）并记日志（只支持 `${workspaceFolder}`） |
| 空数组 / 空条目 | 走第 2 层 |

多个条目的解析结果**按书写顺序拼接**（顺序就是"先在哪找"的优先级），最后去重。

## 实现位置（三层各由谁负责）

| 来源 | 规则（analysis 层，纯逻辑） | 环境读取（provider 层，全在 `providers/box-roots.ts`） |
|---|---|---|
| 来源1 配置 | `rootsFromConfig(entries, workspaceFolders)`：逐条目展开（绝对路径直读；`${workspaceFolder}` 与相对路径按工作区文件夹展开） | ✅ 配置项已在 `package.json` 声明（`r-toolkit.boxPaths`，字符串数组，默认 `[]`）；`readBoxPathsSetting()` 用 `workspace.getConfiguration('r-toolkit').get('boxPaths')` 读 |
| 来源2 box.path | `findNearestRprofile(stDir, stStopDir, exists)` + `parseBoxPathRoots(text, dir)` | ✅ `readNearestRprofile(uri)`：用 `workspace.getWorkspaceFolder(uri)` 取边界 → 找 `.Rprofile` → 读它的文本 |
| 来源3 工作区根 | `rootsFromWorkspace(workspaceFolders)` | ✅ `workspaceFolderPaths()`：读 `workspace.workspaceFolders` |
| 编排 | `collectCandidateRoots({ config, boxpath, workspace })` | ✅ `resolveBoxRoots(uri)`：把环境读成三层原料，交给编排 |
| 模块文件定位 | `resolveModuleFilePath(baseDirs, segments, segmentIndex, exists)` + `baseDirsForImport(relative, fileDir, rootDirs)`（`analysis/module-file.ts`） | ✅ `definition.ts` 传 `fs.existsSync` 做存在性判断 |
| 诊断输出 | — | ✅ OutputChannel `R Toolkit`：模块文件找不到时写「模块路径 + 候选根」 |

> 一句话：**规则在 analysis（可单测），读盘/读设置/写日志在 provider**。
> 已落地：候选根三层解析 → 模块文件定位 → `definition.ts` 加载依赖文件（跨文件类跳转靠它）。
> **尚未落地：点击模块名本身跳转**（`box::use(R/schema/schema)` 里点 `schema` 跳到 `schema.R`）。

> 已知限制：`.Rprofile` 里的 `box.path` **只取第一个**（重复定义属不规范写法，不做兼容）；配置项 `r-toolkit.boxPaths` 支持**多个根**（数组，按书写顺序试）。

## `.Rprofile` 写法 → box 根（最简版）

示例统一假设：`.Rprofile` 所在目录 = `D:\workspace\demo`（即项目根）。

| 写法 | 算出的根 |
|---|---|
| `options(box.path = "D:/workspace/demo")` | `D:\workspace\demo` |
| `options(box.path = './R')` | `D:\workspace\demo\R`（相对路径以 `.Rprofile` 所在目录为基准） |
| `options(box.path = '../shared')` | `D:\workspace\shared` |
| **其它任何写法**（`getwd()`、`here::here()`、`file.path(getwd(),"R")`、`c(...)` 向量、值漏写…） | **回落** `D:\workspace\demo`（`.Rprofile` 所在目录） |
| 没有 `box.path` 这行 | 本层不给结果 → 用第 3 层 |

依据：R 只在**启动目录**读 `.Rprofile` → 它生效 ⇒ 该目录就是 R 启动处、也就是 `getwd()`。

### 已知限制：动态写法**有意不解析**（本期）

`getwd()` / `here::here()` / `normalizePath(...)` / `file.path(getwd(), "R")` / `paste0(...)` / `c("a","b")` 向量等**一律不识别**，统一回落到 `.Rprofile` 所在目录。留痕原因：

- 静态求值动态表达式**不可靠**（`getwd()` 取决于 R 从哪启动；`here::here()` 用另一套找根算法）
- 而"`.Rprofile` 所在目录"在绝大多数项目里就等于 box 根 —— 你项目里的 `options(box.path = getwd())` 正好属于这种
- 猜错也不会跳错：候选根只是"待试目录"，最终由**文件是否存在**裁定（宁可不跳，不乱跳）

将来若真需要，再按需加（都不难）：识别 `getwd()`/`here()` → 视为所在目录；`file.path(getwd(), "R")` → 所在目录 + 字面尾段；`c(...)` → 多候选。

### 已知限制：重复定义 `box.path` 不做兼容（本期）

同一个 `.Rprofile` 里出现多次 `box.path`（`options(box.path = "a", box.path = "b")` 这种同调用内重复传参，或多个 `options()` 调用各写一次）属**不规范写法**，本期**不做兼容**：实现按"**找到第一个就返回**"处理。R 里其实是"后写生效"，差异只在这种不规范代码上。

## 失败诊断

不静默失败：往 OutputChannel `R Toolkit` 写"候选根及来源、试过的路径、命中/全灭"。
