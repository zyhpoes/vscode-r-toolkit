### 3.3 从这张表能得出什么

- **一共 22 条**，其中真正需要"解析逻辑"的只有 **11 条**（5~19），其余是词法就能定。
- 有两处容易搞错的细节（实测得出，写代码时要记住）：
  - `TRUE` / `FALSE` / `NA` / `Inf` **不是名字**（`is.name` 为 FALSE），是常量。
  - `x@y` 的 `y` 在 R 的内部词法表里标成 `SLOT`，但**树里和 `$` 的右边一样都是普通名字** ——

- `f(a, )` 是合法的（空实参），清单里要允许。
- 需要额外补的是「语句层」：换行 / `;` 分隔的表达式序列 → `Program`（文件）与 `BlockExpr`（`{ }`）。

## 4. 树长什么样、优先级怎么确定

### 4.0 先说清三种东西（不然容易吵错）

| | R 的 **AST**（`parse` + `as.list`） | R 的 **CST**（`getParseData`） | **我们要的** |
|---|---|---|---|
| 括号 `(a)` | 保留（`(` 是个调用，实测 `as.list` 长度 2） | 保留（有 token） | **丢掉**（语义等价） |
| 分号 / 注释 | 没有 | 有（`';'`、`COMMENT` 各一行） | 注释留在 token 层，**不进树** |
| 每个节点的起止位置 | 没有（`as.list` 之后全丢） | 有（每 token 的 `line1`/`col1`） | **每个节点都要** |
| 节点类型 | 隐式（靠"第几个位置"） | 显式 | 显式 |

→ **结论**：我们要的是 **"带位置的 AST"** —— 形状像 AST（好写语义），但每个节点带 `stOffset` / `enOffset`
（能算行列、能跳转）。不是纯 CST，也不是纯 AST。

### 4.1 直接看 R 把代码拆成什么（`Rscript evidence/demo2.R` 的真实输出）

`[[k]]` 表示"它在父节点里是第几个位置" —— 这个标注是必须的，因为 **R 的树里没有 `else` / `in` / `=` 这类节点**，
它们只是位置。

```
# a$b$c                 # 1 + 2 * 3              # if (a) b else c
$                        +                        if
  [[2]]   $                [[2]] 1                  [[2]] a      ← 条件
    [[2]] a                [[3]]   *                [[3]] b      ← then
    [[3]] b                  [[2]] 2                [[4]] c      ← else（树里没有 else 节点）
  [[3]] c                    [[3]] 3

# for (i in 1:3) print(i)
for
  [[2]] i          ← 循环变量
  [[3]]   :        ← 序列表达式 1:3（树里没有 in 节点）
    [[2]] 1
    [[3]] 3
  [[4]]   print    ← 循环体
    [[2]] i
```

### 4.2 从上面能直接读出的结论

| 结论 | 从哪个例子看出来 |
|---|---|
| 优先级**不用记表**：更紧的运算符成更深的子节点 | `1 + 2 * 3` 里 `*` 是 `+` 的孩子 |
| `^` 比 `*` 更紧 | `1 + 2 * 3 ^ 4`：`3 ^ 4` 才是 `*` 的孩子 |
| 一元 `-` 比 `+` 紧 | `-x + y`：`-x` 是 `+` 的孩子 |
| `$` **左结合**（`a$b$c` = `(a$b)$c`） | `a$b$c` 里外层 `$` 的左孩子是内层 `$` |
| 用户自定义 `%op%` 是中缀，头就是它自己 | `a %in% b` 的头是 `%in%` |
| 原生管道求值等价于调用：`x |> f()` = `f(x)` | `x |> f()` 的头是 `f`，参数是 `x` |
| `::` 也是中缀 | `pkg::fn` 的头是 `::` |
| **`else` / `in` / `;` 都不是节点** | `if` 的第 4 个位置是 else 分支；`for` 的第 3 个位置是序列 |

### 4.4 从 `tree-sitter-r` 的 grammar 学到的 6 条

数据来源：`docs/tree-sitter-r-grammar.json`（tree-sitter-r 的生成后语法，70 KB）。
本机 npm 上**没有**可用的 R grammar，GitHub 也拉不到，所以这份文件是手动下载留存的参考。

| # | 它怎么做 | 我们照做 / 不照做 |
|---|---|---|
| 1 | 规则共 66 个，其中 **27 个下划线开头** = 内部规则，**不出现在树里** → 真正出现在树里的节点只有 39 种 | **照做**：内部规则加 `_` 前缀，语义层只看真节点 |
| 2 | **括号不建节点**，挂成父节点的 `open` / `close` **字段** | **照做，但按我们自己的命名**：字段叫 `openSpan` / `closeSpan`，AST 里去掉 |
| 3 | **逗号是 named 节点**（`comma`）；**分号是内部规则**（`_semicolon`），不出现 | **照做**：`Comma` 建节点，`;` 不建 |
| 4 | 运算符只有 4 种节点（`unary_operator` / `binary_operator` / `extract_operator` / `namespace_operator`），符号存在 `operator` 字段 | **照做**：`$` 与 `@` 共用"取成员"节点（与 `demo2.R` 的实测一致：两者右边都是普通名字） |
| 5 | `extras` = `comment` + 空白 → **注释不属于任何节点** | **照做**：注释单独收集，不进树 |
| 6 | `externals` 里有 `_newline` / `_semicolon` / `_external_else` / 括号开闭等 **手写扫描器**处理的部分 | **照做但要记代价**：R 的换行、分号、`else` 的位置都是上下文相关的，光靠 BNF 写不出来，必须手写规则 |

第 6 条是这次最大的收获：**R 的"难"不在表达式，而在换行 / `else` 的上下文规则**。

### 4.5 节点清单（CST 与 AST）

两层的差别**比想象的小**：AST 就是"CST 去掉纯语法的东西"。真正的差别只有这些：

| 只有 CST 有 | 说明 |
|---|---|
| `Comma` 节点 | 逗号本身（AST 靠"列表有几个元素"表达，不需要逗号） |
| `Error` / `Missing` 节点 | 认不出的片段 / 缺了但能推断的东西（补全时需要它们） |
| `openSpan` / `closeSpan` / `elseSpan` 字段 | 括号和 `else` 关键字的位置（格式化要用，语义不用） |

**完整的 26 种定义写在代码里**（`src/parser/cst.ts`，将来才建），文档不抄 —— 抄一遍必漂。
这里只留三条规律：

- **一种 R 写法 → 一个 `kind`**：`p$name` 是 `Extract`、`f(a)` 是 `Call`、`a + b` 是 `BinaryOp`、
  `if` 是 `If`、`function` 是 `Function`、`{ }` 是 `Block`、整个文件是 `Program`。
- **只有"表达式 / 名字 / 字面量 / 参数 / 逗号"进树**：关键字（`if` `for` `in` `else` `function`）、
  符号（`(` `)` `;` `<-` `+` `$` `::`）、换行、注释**都不是节点**，一律变成父节点的字段。
- **不存 `text` 字段**：要原文时用 `stOffset` / `enOffset` 去切源码，省内存也不会和源码不同步。

> 括号的命名跟着项目既有约定走：字符是 `openChar` / `closeChar`、token 是 `openToken` / `closeToken`、
> 区间就叫 **`openSpan` / `closeSpan`**。

#### AST 节点（23 种 = CST 去掉 `Comma` / `Error` / `Missing`）

其余 23 种与 CST **同名同字段**，只去掉 `openSpan` / `closeSpan` / `elseSpan` 这几个纯位置字段。
好处：语义代码只面对 23 种、不需要判 `Comma`；格式化器拿到 CST 仍能看到逗号和括号位置。

### 4.6 三个例子（CST 与 AST 的代码对照）

#### 例子一：`f(a, b = 2)`

```ts
// CST —— 有逗号、有括号位置
{
  kind: 'Call',
  callee: { kind: 'Identifier', text: 'f', stIndex: 0, enIndex: 0, stOffset: 0, enOffset: 1 },
  openSpan:  { stIndex: 1, enIndex: 1, stOffset: 1, enOffset: 2 },              // "("
  arguments: [
    { kind: 'Argument', value: { kind: 'Identifier', text: 'a', … } },
    { kind: 'Comma', stIndex: 3, enIndex: 3, stOffset: 3, enOffset: 4 },        // 逗号
    { kind: 'Argument',
      name:  { kind: 'Identifier', text: 'b', … },
      value: { kind: 'Literal', literalKind: 'number', … } },
  ],
  closeSpan: { stIndex: 7, enIndex: 7, stOffset: 10, enOffset: 11 },            // ")"
  stIndex: 0, enIndex: 7, stOffset: 0, enOffset: 11,
}

// AST —— 逗号和括号都没了，其余一模一样
{
  kind: 'Call',
  callee: { kind: 'Identifier', text: 'f', … },
  arguments: [
    { kind: 'Argument', value: { kind: 'Identifier', text: 'a', … } },
    { kind: 'Argument', name: { kind: 'Identifier', text: 'b', … },
      value: { kind: 'Literal', literalKind: 'number', … } },
  ],
  stIndex: 0, enIndex: 7, stOffset: 0, enOffset: 11,     // 区间不变（仍覆盖整段）
}
```

#### 例子二：`if (a) b else if (c) d else e`（`else if` 就是**嵌套**，实测 R 的 `parse` 如此）

```ts
{
  kind: 'If',
  openSpan:    Span,                    // "("
  condition:   { kind: 'Identifier', text: 'a', … },
  closeSpan:   Span,                    // ")"
  consequence: { kind: 'Identifier', text: 'b', … },
  elseSpan:   Span,                    // 第 1 个 "else"
  alternative: {
    kind: 'If',                         // ← 嵌套一个 If，不需要新节点类型
    openSpan:    Span,
    condition:   { kind: 'Identifier', text: 'c', … },
    closeSpan:   Span,
    consequence: { kind: 'Identifier', text: 'd', … },
    elseSpan:   Span,                  // 第 2 个 "else"
    alternative: { kind: 'Identifier', text: 'e', … },
  },
}
```

`elseSpan` 的位置有用：R 里 `} else {` 和 `}\nelse {` **语义不同**（换行后 `else` 会变成新语句），
格式化器要靠它判断。`call` 长度区分不了 `else c` 和 `else if …`（都是 4），要看第 4 个的类型。

#### 例子三：`p$name`

```ts
// 两层共用，只差 operator 的位置没被 AST 丢弃也无所谓
{
  kind: 'Extract',
  target:   { kind: 'Identifier', text: 'p', … },
  operator: { text: '$', stIndex: 2, enIndex: 2, stOffset: 1, enOffset: 2 },   // 是 $ 还是 @
  member:   { kind: 'Identifier', text: 'name', … },
  stIndex: 0, enIndex: 4, stOffset: 0, enOffset: 6,

```

### 4.7 字段清单里容易漏的 5 处（写代码前先记住）

| # | 缺口 | 例子 | 为什么需要 |
|---|---|---|---|
| 1 | `Program` / `Block` 要有 `separators: Span[]` | `{ a; b }` vs `{ a` ⏎ `b }` | 格式化要把 `;` 和换行互转，否则看不出来 |
| 2 | `Argument.value` 必须**可缺** | `f(a, )` | 实测：空实参是**合法** R |
| 3 | 取子集的下标必须**允许空位** | `x[1, ]` / `x[, 1]` | 同上（省略的参数） |
| 4 | `literalKind` 要含 `'complex'` | `1i` | R 有复数（`demo2.R` 里出现） |
| 5 | `Function.keyword` 要记写法 | `function(x) x` vs `\(x) x` | 格式化要保留用户写的那个 |

### 4.8 六项已定的细节（2026-10-29 与用户逐条确认）

**① 注释：扁平存，分两类**

```ts
interface CstProgram extends Span {
  kind: 'Program';
  body: CstExpr[];
  separators: Span[];
  ownLineComments: CstComment[];     // 独占一行的注释
  trailingComments: CstComment[];    // 跟在代码同一行后面的注释
}
interface CstComment extends Span { kind: 'Comment'; text: string }
```

为什么不挂在节点上：**无归属的注释没地方放**（文件头注释、空行隔开的注释、只有注释的文件）。
归属由用的人按位置算 —— "同一行"就是尾注释，"紧挨着下一个语句"就是它的前导注释。
（Python 同理：`#` 注释不归属任何节点；"属于模块的说明"是 docstring，不是注释。）

**② `CstExpr` 含 `Error`，AST 的 `Expr` 不含**

`f(a, $b)` 这种写错的代码，CST 里出错的那段是 `Error` 节点；转成 AST 时丢掉。
这样语义层永远见不到 `Error`，而 `CstExpr` 不用在十几个字段上写 `| CstError`。

**③ 哪些东西不进树**：见 §4.5 的第 2 条规律。

**④ 优先级表**：由 R 实测生成（不是设计决定）。做法：对 `a OP1 b OP2 c` 每一对跑 `parse`，
看谁落在更深层 —— 同时也能确定结合性（`a - b - c` 左结合、`a ^ b ^ c` 右结合，都以实测为准）。

**⑤ `Missing` 的 `expected` 五种**：`')'` / `']'` / `'}'` / `'expression'` / `'name'`。
用途：补全提示"这里该写什么"、格式化补上缺失的收尾符号。以后遇到新的再补。

```ts
interface CstMissing extends Span { kind: 'Missing'; expected: ')' | ']' | '}' | 'expression' | 'name' }
```

**⑥ 不区分"语句"和"表达式"**

R 里一切都是表达式：`42` 单独一行合法、`if (a) b` 能当值、`x <- 1` 也是表达式。
所以 `Program.body` / `Block.body` 都是 `CstExpr[]`。
如果分成两套类型，`f(x = 1)` 的具名参数、单独一行的 `42` 都要多包一层壳。

### 8.4 建议的 5 个阶段（每阶段都能单独验收）

| 阶段 | 交付 | 用户能看到变化吗 | 怎么验收 |
|---|---|---|---|
| **P1** | CST 解析器 + 一个打印树的脚本（不接 provider） | 否 | 拿 `evidence/demo2.R` 的输出逐条对照 |
| **P2** | 换行 / 分号 / `else` 规则 + 错误恢复（写一半的代码也行） | 否 | 真实 R 文件（含写一半的）都能出树 |
| **P3** | CST → AST + `bindings` 改成从 AST 取 | **是**：`p = Person$new()` 之后 `p$` 有候选了 | 现有测试 + 新场景 |
| **P4** | 作用域层 | **是**：函数里的局部变量、形参能跳 / 能补 | 新场景 |
| **P5** | `r6-parser` 改成吃 AST | 是（R6 功能全部走新树，行为应不变） | 405 个测试全绿 |

### 8.5 不做的代价（也列清楚）

| 不做 | 后果 |
|---|---|
| 跳转 / 补全的正确性 | 只在 R6 子集里靠谱；`p = Person$new()`、函数内局部变量、形参名都不行 |
| 加新功能 | 每加一个都要**再写一遍 token 扫描**（A2 的区间 bug、A4 的单表达式体都是这么来的） |
| 维护 | 5 个解析器各自处理边界，同类 bug 会继续出 |
