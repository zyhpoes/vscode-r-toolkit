# 技术债

> 已知但尚未处理的问题清单 —— 目的是"不用通读代码也知道欠了什么"。
> 维护规则：只记事实与状态，不复制实现细节（细节一律给代码路径）；**本文件只放"待修 / 待定"的事**——
> 修完的直接删（历史在 git 里）；确认**不做**的写进对应决策文档（`docs/box-模块规则.md` 的「本插件 v1 的范围」、`DESIGN.md` 的「技术债与已知限制」）后也从这里删。
> 位置一律写「文件 + 符号名」，**不写行号**：行号是位置不是身份，上面随便改几行它就漂了（本项目实际踩过两次）。
> 状态用词：`待定` = 需要用户拍板；`待验证` = 读代码推演得到、尚未用测试确认；`待做` = 已确认、尚未处理。
> 组别即优先级：A 影响用户可见行为 > B 误导读代码的人 > C 可靠性隐患 > D 命名与卫生。
> 对外部系统（box / R / VS Code）的行为断言，标注是**实测**还是**推理** —— 推理被当成定论已经害过两次（模块别名语义、字符串路径）。

## A. 功能缺口与语义未定

> R6 语义专项：本组的「实测事实」都是在**本机 R（项目库里的 R6）上真跑出来的**，不是读文档推的。
> `类名$` 那条已修完：口径（以 `ls()` 默认输出为准）与结论记在 `DESIGN.md` 的「技术债与已知限制」。

| A1 | 实例侧补全没给 R6 自带的 `clone` | `src/analysis/completion.ts` 的 `r6MemberCandidates`（非生成器那一支，末尾注释里标了这个位置） | 实测 R6 2.6.1：`ls(实例)` = 用户成员 + `clone`；`self$clone` 是函数；`private$clone` **不是**（私有环境里只有用户写的 `secret`）；生成器上它叫 `clone_method`（已在槽表里） | 待做（2026-10-09 决定先记账不做——价值低。改法：照 `R6_GENERATOR_SLOTS` 的样式在 `src/analysis/members.ts` 加实例侧常量，`self$`/实例 `$` 读它；`private$` 不给；`super$` **未测** → 也不给） |

| A3 | 参数 / 具名元素的名字没有定义跳转：`function(y = 3) y` 里点函数体的 `y`、`f(x = 2)` 里点 `x`，都该跳到形参处 | `src/analysis/bindings.ts` 的 `parseBindings`（只认 `<-`、无括号深度）、`src/analysis/module-symbols.ts` 的 `parseTopLevelSymbols`（有深度、认 `=`） | **决定**（2026-10-09）：补 `=` 之前，形参 / 具名元素 / 具名实参必须**另立 kind**，不能并进"变量赋值"——反例 `p <- Person$new(); f(p = 1); p$` 会把 `f(p = 1)` 当成 p 的最近赋值 → 类型推断取到 `1` → **给出错的候选**（比"少给"严重）。现状与 `=` / `<-` 的实测差异见 `DESIGN.md`「技术债与已知限制」第一条 | 待定（前提：一张带 kind 的符号表 + 作用域；另：`f(x = 2)` 要跳到 `f` 的形参得先有 `f` 的定义，包函数拿不到签名 → 覆盖会不一致、收益打折） |
