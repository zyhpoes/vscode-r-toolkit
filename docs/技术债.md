> 已知但尚未处理的问题清单 —— 目的是"不用通读代码也知道欠了什么"。
> 维护规则：只记事实与状态，不复制实现细节（细节一律给代码路径）；修完的条目直接删掉（历史在 git 里）。

## 不算债（明确决定，或已记录的范围）

- `[...]`（附着全部）不提供跳转 —— 明确决定，理由见 `docs/box-模块规则.md:65`
- 非 ASCII 标识符、跨模块继承深度 > 1、`B$A$a`、`s <- schema`、再导出 —— 已记录的范围与限制，见 `docs/box-模块规则.md:53`
- 每次跳转都重新解析、候选逐个试、线性找 token —— 微秒级，无需优化
- `exists` 与两张表（模块名映射、附着名映射）由 provider 注入 —— 分层设计，见 `DESIGN.md:101`，不是债
