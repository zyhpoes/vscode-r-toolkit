# box 模块规则（本插件视角）

> 状态：设计约定，尚未实现（进度见 `DESIGN.md`）。改动本文件规则需经用户同意。

## 模块形态

| 形态 | 例子 | 导入写法 |
|---|---|---|
| 文件模块 | `R/schema/schema.R` | `box::use(R/schema/schema)` |
| 目录模块 | `R/bio/__init__.r`（目录的入口文件） | `box::use(R/bio)` |

试文件顺序（在候选根下）：`<模块路径>.R` / `.r` → `<模块路径>/__init__.R` / `.r`，第一个存在的胜出。

本地模块 vs 已安装包：**按文件存在性判定** —— 两种形态都不存在 → 视为已安装包，不跳转。
（不能按"路径里有没有 `/`"判断：`box.path = './R'` 时 `box::use(subject)` 不含 `/`，但它确是本地文件 `D:\workspace\demo\R\subject.R`）

## 导出什么（决定 `模块$` 补全列出哪些名字、`模块$xxx` 能不能跳）

### 我们的 v1 规则（**宽松**，用户决定，优先于下面的 box 真实规则）

| 模块文件里的情况 | 给不给跳转 / 补全 |
|---|---|
| 顶层赋值（函数 / 常量 / R6 类），名字不以 `.` 开头 | ✅ 给 |
| 名字以 `.` 开头（R 的"隐藏名"惯例） | ❌ 不给 |
| 有没有 `#' @export` 标记 | **一律不看** —— 就按"没有标记"处理 |
| 有没有 `box::export()` | **同样不看** |
| 函数体 / `{}` 块内部的局部变量 | ❌ 不算顶层，不给 |

一句话：**把每个模块都当成 box 的 legacy module 对待**。

**为什么这么定**：静态工具的价值是"导航"，不是"运行时校验"。若按 box 严格规则做，模块里只要出现**一个**
`#' @export`，其余名字就全部不可跳 —— 用户会碰到"函数明明就在那个文件里，F12 却没反应"，这是最恼火的失败方式。
而箱底的"无标记 → 全部非隐藏名"规则本来就已覆盖本项目 100% 的现状
（`clin-event-lab-link` 全项目 0 个 `@export`、0 个 `box::export()`）。

**代价（明确认下）**：如果某个模块**故意**用 `#' @export` 限制导出（只公开一部分 API），
我们也会把内部名给出来（跳转 + 补全）。即放弃"工具帮我挡住误用"，换"工具不挡路"。

### box 的真实规则（参考；将来若要做严格模式按这个来）

| 模块文件里的情况 | box 实际导出的名字 |
|---|---|
| 有 `#' @export` 标记 | **只有被标记的名字** |
| **一个 `#' @export` 都没有** | **所有非隐藏名**（不以 `.` 开头） |
| 写了 `box::export()` | **零导出**（显式声明"我是 box 模块，不导出任何名字"） |
| `#' @export` 写在 `box::use(...)` 前 | 该导入声明的名字**再导出**（如 `bio$seq`） |

依据（box 官方 migration 指南原文）：

> "‘box’ makes exporting explicit. By default, *no* names are exported from a module, unless they are marked with the directive comment `#' @export`"
> "There's one exception to this: if a module contains *no* declared export, ‘box’ assumes that it is a plain R script, and treats it as a *legacy module*. This causes ‘box’ to revert to the export behaviour of ‘modules’"（即导出所有非隐藏名）

## 本插件 v1 的范围

| 能力 | v1 |
|---|---|
| 提取顶层符号 | 只提**顶层**赋值（函数 / 常量 / R6 类）；函数体内部的局部变量不算；以 `.` 开头的隐藏名不算 |
| 显式附着 `[a, b]` / `[g = f]` | ✅ **完整支持**：点 `a` / `g` 跳到模块里对应的定义（`g` 用右侧的源名去找） |
| `[...]`（附着全部） | **不做**（原因见下） |
| 空附着 `pkg[]` | 按 box 语义处理：**不绑模块名、也不引入任何名字**（`moduleBindingName` 返回 undefined） |
| `#' @export` 标记 | **不解析、不生效**（一律按"没有标记"处理，见上） |
| `box::export()` | **不解析、不生效**（同上） |
| `#' @export box::use(./seq)` 的再导出 | **不做**（`bio$seq` 这类补不出来；点 `bio` 跳到 `__init__.r` 不受影响） |

### 已知限制：`[...]`（附着全部）不提供跳转

`box::use(mod[...])` 会把模块的**全部**导出名一次铺进当前作用域。我们对它的名字**不做跳转**，原因：

- **撞名无法避免**：多个模块同时用 `[...]` 时大量重名。运行时的规则是"**后导入者覆盖先导入者**"，而我们的查询固定"本地优先、附着兜底"，**没有建模这个先后顺序** → 硬猜就会**跳错地方**（我们宁可"不跳"也不"跳错"）。
- **与设计哲学相悖**：本插件的跨文件方案建立在"**按需导入、显式列出**"之上（见 `DESIGN.md` 的方向决策）；`[...]` 恰恰是"不说清用了什么"。
- **旁证**：PEP 8 对 Python 的同类写法 `from mod import *` 明确写"应当避免"，理由正是"让读者**和自动化工具**都无法判断作用域里有哪些名字"——而我们就是那个自动化工具。

**替代写法**：需要少打字时用显式附着 `box::use(mod[a, b])` —— 它**完整支持跳转**。

失败方式：点了**没反应**（不会跳到错的地方）。
