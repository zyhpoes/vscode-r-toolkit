# 补全覆盖面总表

> 用途：一眼看清"哪些补全归我们管、各自现状如何、哪些明确不做"。
> 本表是**覆盖面**的定义，不是进度表：现状列用 ✅ 已做 / ⚠️ 部分或有已知偏差 / ❌ 没做 / — 不该做。
> 口径变化时同步更新本表。R6 的运行时语义（实测值）记在 `DESIGN.md`，这里只引用不复制。

## 一、按访问形态分类

| 形态 | 左边是什么 | 能列什么 | 谁负责 | 现状 | 备注 |
|---|---|---|---|---|---|
| `x$` | **环境** | 环境里的绑定 | 我们 / vscode-R | ⚠️ | 目前只覆盖 R6 三个关键字名 |
| `x$` | **list** | 元素名 | 我们 / vscode-R | ❌ | R 对 list 的 `$` 支持**部分匹配**（`l$na` 命中 `name`） |
| `x$` | **data.frame / tibble** | 列名 | 待实测 | ❌ | 使用面最大的一块，**归属要先测**（见第四节） |
| `x$` | **R6 生成器** | R6 自带 25 个（24 槽 + 合成的 `new`） | **我们** | ✅ | 用户成员在生成器上取不到 |
| `x$` | **R6 实例** | public + active + `clone` | **我们** | ⚠️ | 缺 `clone` |
| `x$` | **S4 对象** | 槽名 | 未评估 | ❌ | `$` 对 S4 是否可用**待实测** |
| `x$` | **S3 对象** | 底层是 list 时列元素名 | 让位 | — | 若定义了 `$.class` 方法 → 静态不可能知道 |
| `x$` | **函数** | —— | — | — | `f$a` 直接报错，函数不是容器 |
| `a$b$c$` | 表达式链 | 由终点类型决定 | **我们** | ✅ | 逐段单步求值 |
| `f()$` | **调用结果** | 取决于函数返回什么 | 未定 | ❌ | 需要"函数返回类型"推断，见第三节 |
| `self$` / `private$` / `super$` | 方法作用域里的预置名 | 见第二节 | **我们** | ⚠️ | 有两处已知语义偏差 |
| `pkg::` | 命名空间 | **导出名** | 我们 / 暂无 | ❌ | DESIGN 第 5 项；v1 未做 |
| `pkg:::` | 命名空间 | 内部名 | **不做** | — | |
| `obj@` | S4 对象 | 槽名 | 未评估 | ❌ | R 的第三种成员运算符 |
| `模块绑定名$` | box 模块 | 模块顶层符号 | **我们** | ⚠️ | 部分（模块成员补全未做） |
| `box::use(...)` 内的**路径段** | 模块路径 | 目录 / 文件 | **我们** | ✅ | 已有 |
| 裸名字 | —— | 变量 / 函数 / 参数 | **vscode-R / VS Code** | — | 我们**不接**，避免抢候选 |
| `f(` 之后的**参数名** | —— | 形参名 | **不做** | — | |
| `attr(x, "` | —— | 属性名 | **不做** | — | |
| `\|>` / `%>%` 之后 | 表达式位置 | 最终仍归到 `$` 或函数 | —— | — | 形态不同，不新增语义 |
| R5 / Rc（Reference Classes） | 另一套 OOP，也用 `$` | `fields()` / `methods()` | 未评估 | ❌ | |

## 二、R6 的五个容器（我们的主战场）

| 容器 | 能列什么 | 现状 | 语义依据 |
|---|---|---|---|
| `private$` | 本类 + 父类的 **private** 成员（字段与函数） | ⚠️ 现在只列本类 | `DESIGN.md` 实测 |
| `self$` | 本类 + 父类的 **public + active**，外加 `clone` | ⚠️ 缺 `clone` | 同上 |
| 实例 `$`（类外） | 与 `self$` 相同 | ⚠️ 缺 `clone` | 同上 |
| `super$` | 父类起、**只给函数类成员**（public 方法 / private 方法 / active / `clone`），**字段一律 NULL** | ⚠️ 现在会给字段 | 同上 |
| 生成器 `$` | R6 自带 25 个 | ✅ | 同上 |

## 三、明确不做

1. **裸名字补全**（变量 / 函数 / 参数）—— 交给 vscode-R 与 VS Code 词补全
2. **参数名补全**（`f(` 之后）
3. **`:::` 内部名**
4. **S3 中 `$.class` 改写过的对象**（静态不可知 → 让位）
5. **动态构造的对象**（rlang / vctrs / 运行期 `setClass` 等）

## 四、待实测

| 事项 | 为什么要测 | 怎么测 |
|---|---|---|
| `df$` 归谁 | 列名是使用面最大的一块；若 vscode-R 已在做，我们不该抢 | 写 `df <- data.frame(a = 1)` 然后 `df$`，看候选由谁提供 |
| S4 的 `$` 是否可用 | 决定除 `@` 之外是否还要管 S4 的 `$` | `setClass` + `new` 后比较 `a$x` 与 `a@x` |

## 五、路线顺序（本轮讨论定）

1. **R6 补全**（最有代表性）
2. **环境 / 包名**
3. **其它**

> 附注：R6 的 `self` / `private` / `super` 本质上就是**环境成员查找**，所以第 1 步与第 2 步共用同一套底层。
